# ADR 0001: Vector Store Selection - ChromaDB Persistent

## Status
Accepted

## Context
SafeStrata requires an embedded, open-source vector store to store and index high-dimensional embeddings generated by local Hugging Face Sentence Transformers (`sentence-transformers/all-MiniLM-L6-v2`).
A critical security requirement is strict Role-Based Access Control (RBAC) at the retrieval layer: queries executed by a caller must only retrieve chunks belonging to documents that their verified role is authorized to read (`allowed_roles`).

## Decision
We select **ChromaDB** in persistent disk mode (`PersistentClient` at `data/chroma`).
- **Metadata Filtering**: ChromaDB natively supports metadata `where` filtering with `$contains` or `$in` operators. Every chunk is stored with `allowed_roles` in its metadata.
- **Local Embedded Operation**: ChromaDB runs fully in-process without requiring external daemon infrastructure or cloud API keys.
- **Persistence**: Vectors, metadata, and collection indices persist across restarts.
- **Collection Isolation**: We maintain a unified collection with strict role-level filters applied at search time.

## Consequences
- **Positive**: Zero external cloud egress, zero latency overhead from remote network calls, deterministic role filtering at the vector store layer preventing vector-space data leakage.
- **Negative**: SQLite-backed Chroma metadata queries must be carefully indexed.
- **Compliance**: Fully complies with RBI banking data localization standards.
